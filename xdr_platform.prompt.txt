# XDR Platform (Extended Detection & Response) - Prompt Specification
## Tech Stack Alignment
MUST USE APPROVED STACK:
- Backend: Node.js 18, Express.js, PostgreSQL 16, Redis 7, RabbitMQ 3, JWT, bcryptjs
- Frontend: React 18, React Router 6, Bootstrap 5, Chart.js, React ChartJS 2 (dashboard)
- Infra: Docker (node:18-alpine), Docker Compose, Kubernetes, Nginx Alpine
- Security: OWASP API Top 10, Helmet, Rate Limiting, JWT Auth via API Gateway

## 1. Component Overview
Extended Detection & Response platform providing cross-domain threat detection by correlating telemetry from endpoints (EDR), network (NGFW), cloud (CSPM), and email with automated response orchestration across all security tools in the platform.

## 2. Core Requirements
- Cross-domain telemetry ingestion (EDR, NGFW, CSPM, Email Security, WAF)
- Behavioral analytics using Risk Engine (Python/FastAPI) for anomaly detection
- Automated correlation across security domains (link related alerts)
- Response orchestration with playbook execution (integration with SOAR)
- Threat hunting interface with query builder and visualization
- Incident timeline reconstruction across multiple data sources
- Integration with Threat Intel for proactive hunting
- Redis caching for correlations, active incidents, threat hunts
- RabbitMQ event publishing for cross-domain correlations, incident creation

## 4. Database Schema (PostgreSQL)
```sql
CREATE TABLE xdr_alerts (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id UUID REFERENCES tenants(id),
  source_type VARCHAR(50) NOT NULL, -- edr, ngfw, cspm, email, waf
  source_alert_id VARCHAR(255), -- original alert ID from source
  title VARCHAR(255) NOT NULL,
  description TEXT,
  severity VARCHAR(20),
  mitre_tactic VARCHAR(100),
  mitre_technique VARCHAR(100),
  source_ip INET,
  dest_ip INET,
  affected_assets UUID[], -- references asset_management
  status VARCHAR(20) DEFAULT 'new', -- new, triaged, investigating, resolved
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE xdr_incidents (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id UUID REFERENCES tenants(id),
  title VARCHAR(255) NOT NULL,
  severity VARCHAR(20),
  status VARCHAR(20) DEFAULT 'open', -- open, contained, resolved
  related_alerts UUID[], -- array of xdr_alerts IDs
  attack_chain JSONB, -- MITRE ATT&CK mapping of tactics used
  assigned_to UUID, -- references IAM user
  timeline JSONB, -- reconstructed attack timeline
  created_at TIMESTAMP DEFAULT NOW(),
  resolved_at TIMESTAMP
);

CREATE TABLE xdr_correlations (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id UUID REFERENCES tenants(id),
  name VARCHAR(255) NOT NULL,
  logic JSONB NOT NULL, -- correlation logic (time window, source types, etc.)
  enabled BOOLEAN DEFAULT true,
  match_count INT DEFAULT 0,
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE threat_hunts (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id UUID REFERENCES tenants(id),
  query_text TEXT NOT NULL,
  data_sources TEXT[], -- edr, ngfw, cspm, email
  results_count INT,
  status VARCHAR(20) DEFAULT 'running', -- running, completed, failed
  findings JSONB,
  started_at TIMESTAMP DEFAULT NOW(),
  completed_at TIMESTAMP
);

CREATE INDEX idx_xdr_tenant ON xdr_alerts(tenant_id, created_at DESC);
```

## 5. Service Integrations
- Redis: Cache correlations, threat hunt results, active incidents (TTL 1h)
- RabbitMQ: Consume from all security event queues, publish to `xdr-incidents`, `xdr-response`
- API Gateway: All endpoints routed through `/api/xdr/*`
- EDR Service: Pull endpoint telemetry, correlate with network events
- NGFW Service: Get network connection data for incident reconstruction
- CSPM Service: Correlate cloud misconfigurations with attacks
- Risk Engine: Send telemetry for behavioral analysis (HTTP to `risk-engine:8000`)
- Threat Intel: Pull IOCs for proactive hunting
- SOAR Service: Execute response playbooks for XDR incidents
- SIEM Service: Sync alert data, avoid duplication
- IAM Service: Validate tenant_id from JWT token, incident assignment

## 6. Security Requirements
- All endpoints protected by API Gateway OWASP policies
- Tenant isolation: queries filtered by JWT tenant_id
- Encrypt sensitive incident data at rest
- Audit logging: all response actions logged to `request_logs`
- Role-based access: only analysts can triage incidents
- mTLS for service-to-service communication
- Data minimization: only store necessary telemetry for investigations

## 7. Deployment
### Dockerfile
```dockerfile
FROM node:18-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production
COPY . .
EXPOSE 3020
HEALTHCHECK --interval=30s --timeout=10s --retries=3 \
  CMD node -e "require('http').get('http://localhost:3020/health', (r) => {process.exit(r.statusCode === 200 ? 0 : 1)})"
CMD ["node", "server.js"]
```

