# DevSecOps Platform - Prompt Specification
## Tech Stack Alignment
MUST USE APPROVED STACK:
- Backend: Node.js 18, Express.js, PostgreSQL 16, Redis 7, RabbitMQ 3, JWT, bcryptjs
- Frontend: React 18, React Router 6, Bootstrap 5, Chart.js (dashboard)
- Infra: Docker (node:18-alpine), Docker Compose, Kubernetes, Nginx Alpine
- Security: OWASP API Top 10, Helmet, Rate Limiting, JWT Auth via API Gateway

## 1. Component Overview
Microservice for integrating security into CI/CD pipelines with automated SAST, DAST, container scanning, dependency checks, and policy-based deployment gating for multi-tenant DevOps environments.

## 2. Core Requirements
- CI/CD integration (GitHub Actions, GitLab CI, Jenkins, Azure DevOps)
- SAST (Static Application Security Testing) scan orchestration
- DAST (Dynamic Application Security Testing) for running applications
- Container image scanning (Docker, Kubernetes manifests)
- Software Composition Analysis (SCA) for dependency vulnerabilities
- Policy-based deployment gating (block insecure deployments)
- Security gates integrated with Vulnerability Scanner and CSPM services
- Redis caching for scan results and policy decisions
- RabbitMQ event publishing for scan completions, policy violations

## 3. API Endpoints (routed via API Gateway: /api/devsecops/*)
| Method | Endpoint | Description | Auth |
|--------|----------|-------------|------|
| GET | /health | Health check | None |
| GET | /api/devsecops/pipelines | List CI/CD pipelines | JWT/API Key |
| POST | /api/devsecops/pipelines | Register new pipeline | Admin JWT |
| GET | /api/devsecops/scans | List security scans | JWT/API Key |
| POST | /api/devsecops/scans | Trigger security scan | Admin JWT |
| GET | /api/devsecops/scans/:id | Get scan results | JWT/API Key |
| GET | /api/devsecops/policies | List security policies | JWT/API Key |
| POST | /api/devsecops/policies | Create deployment policy | Admin JWT |
| GET | /api/devsecops/gates | Check deployment gate status | JWT/API Key |
| GET | /api/devsecops/metrics | Get DevSecOps metrics | JWT/API Key |

## 4. Database Schema (PostgreSQL)
```sql
CREATE TABLE devsecops_pipelines (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id UUID REFERENCES tenants(id),
  name VARCHAR(255) NOT NULL,
  ci_cd_platform VARCHAR(50), -- github, gitlab, jenkins, azure_devops
  repo_url VARCHAR(500),
  webhook_secret_encrypted TEXT,
  status VARCHAR(20) DEFAULT 'active',
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE security_scans (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id UUID REFERENCES tenants(id),
  pipeline_id UUID REFERENCES devsecops_pipelines(id),
  scan_type VARCHAR(50) NOT NULL, -- sast, dast, container, sca
  target VARCHAR(500), -- repo, image, URL
  status VARCHAR(20) DEFAULT 'pending', -- pending, running, completed, failed
  findings_count INT DEFAULT 0,
  severity_breakdown JSONB, -- {critical: 0, high: 0, medium: 0, low: 0}
  scan_results JSONB,
  started_at TIMESTAMP,
  completed_at TIMESTAMP
);

CREATE TABLE deployment_policies (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id UUID REFERENCES tenants(id),
  name VARCHAR(255) NOT NULL,
  rules JSONB NOT NULL, -- max critical vulns, required scans, etc.
  enforcement_mode VARCHAR(20) DEFAULT 'audit', -- audit, block
  enabled BOOLEAN DEFAULT true,
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE deployment_gates (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id UUID REFERENCES tenants(id),
  pipeline_id UUID REFERENCES devsecops_pipelines(id),
  deployment_id VARCHAR(255),
  gate_status VARCHAR(20), -- pass, fail, pending
  policy_results JSONB,
  gated_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_devsecops_tenant ON security_scans(tenant_id);
```

## 5. Service Integrations
- Redis: Cache scan results, policy decisions, gate status
- RabbitMQ: Publish to `devsecops-events` queue (scan.completed, gate.failed, policy.violation)
- API Gateway: All endpoints routed through `/api/devsecops/*`
- Vulnerability Scanner: Pull CVE data for dependency/container scans
- CSPM Service: Check cloud deployment configurations
- GRC Service: Map scan findings to compliance controls
- IAM Service: Validate tenant_id from JWT token

## 6. Security Requirements
- All endpoints protected by API Gateway OWASP policies
- Tenant isolation: queries filtered by JWT tenant_id
- Encrypt webhook secrets at rest
- Audit logging: all policy changes and gate decisions logged to `request_logs`
- mTLS for service-to-service communication
- Least privilege: CI/CD tokens with minimal permissions

## 7. Deployment
### Dockerfile
```dockerfile
FROM node:18-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production
COPY . .
EXPOSE 3014
HEALTHCHECK --interval=30s --timeout=10s --retries=3 \
  CMD node -e "require('http').get('http://localhost:3014/health', (r) => {process.exit(r.statusCode === 200 ? 0 : 1)})"
CMD ["node", "server.js"]
```

### Docker Compose Block
```yaml
devsecops:
  platform: linux/amd64
  build:
    context: ./devsecops-service
    dockerfile: Dockerfile
  container_name: cybersec-devsecops
  ports:
    - "3014:3014"
  environment:
    NODE_ENV: production
    PORT: 3014
    DATABASE_URL: postgresql://cybersec:securepassword@postgres:5432/cybersec_platform
    REDIS_URL: redis://redis:6379
    RABBITMQ_URL: amqp://cybersec:securepassword@rabbitmq:5672
    VULN_SCANNER_URL: http://vuln-scanner:3004
    CSPM_SERVICE_URL: http://cspm:3011
  depends_on:
    postgres:
      condition: service_healthy
    redis:
      condition: service_healthy
  healthcheck:
    test: ["CMD", "node", "-e", "require('http').get('http://localhost:3014/health', (r) => {process.exit(r.statusCode === 200 ? 0 : 1)})"]
    interval: 30s
    timeout: 10s
    retries: 3
  networks:
    - cybersec-network
```

## 8. Testing
- Jest unit tests for policy engine, gate evaluation logic
- Health check: `GET /health` returns 200
- Test scan trigger: `POST /api/devsecops/scans` returns 202 (accepted)
- Test deployment gate: `GET /api/devsecops/gates?deployment_id=123` returns pass/fail
- Test tenant isolation: JWT from tenant A cannot access tenant B pipelines
- Align with platform `test-platform.js` script
