# Human Risk Awareness Platform - Prompt Specification
## Tech Stack Alignment
MUST USE APPROVED STACK:
- Backend: Node.js 18, Express.js, PostgreSQL 16, Redis 7, RabbitMQ 3, JWT, bcryptjs
- Frontend: React 18, React Router 6, Bootstrap 5, Chart.js, React ChartJS 2 (dashboard)
- Infra: Docker (node:18-alpine), Docker Compose, Kubernetes, Nginx Alpine
- Security: OWASP API Top 10, Helmet, Rate Limiting, JWT Auth via API Gateway

## 1. Component Overview
Microservice for security awareness training, phishing simulations, human risk scoring, and behavioral change tracking with integration to Risk Engine (Python/FastAPI) for dynamic risk calculation across multi-tenant environments.

## 2. Core Requirements
- Training campaign management (create, schedule, track completion)
- Phishing simulation engine (email templates, landing pages, tracking)
- Course library with progress tracking and quiz assessments
- Human risk scoring per user/department (integration with Risk Engine)
- Automated reminders and escalation workflows
- Integration with IAM for user sync and risk profile updates
- Redis caching for campaign status, user scores, training content
- RabbitMQ event publishing for campaign completion, phishing clicks, high-risk users

## 4. Database Schema (PostgreSQL)
```sql
CREATE TABLE awareness_campaigns (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id UUID REFERENCES tenants(id),
  name VARCHAR(255) NOT NULL,
  type VARCHAR(50), -- training, phishing, policy_review
  status VARCHAR(20) DEFAULT 'draft', -- draft, active, completed
  start_date DATE,
  end_date DATE,
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE training_courses (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id UUID REFERENCES tenants(id),
  title VARCHAR(255) NOT NULL,
  description TEXT,
  content_url VARCHAR(500),
  duration_minutes INT,
  quiz_questions JSONB,
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE user_training (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id UUID REFERENCES tenants(id),
  user_id UUID NOT NULL, -- references IAM user
  course_id UUID REFERENCES training_courses(id),
  campaign_id UUID REFERENCES awareness_campaigns(id),
  status VARCHAR(20) DEFAULT 'assigned', -- assigned, in_progress, completed, failed
  quiz_score DECIMAL(5,2),
  started_at TIMESTAMP,
  completed_at TIMESTAMP
);

CREATE TABLE phishing_simulations (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id UUID REFERENCES tenants(id),
  campaign_id UUID REFERENCES awareness_campaigns(id),
  template_name VARCHAR(255),
  target_users UUID[], -- array of IAM user IDs
  emails_sent INT DEFAULT 0,
  clicks_count INT DEFAULT 0,
  credentials_submitted INT DEFAULT 0,
  reported_count INT DEFAULT 0,
  sent_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE human_risk_scores (
  id BIGSERIAL PRIMARY KEY,
  tenant_id UUID REFERENCES tenants(id),
  user_id UUID NOT NULL,
  risk_score DECIMAL(5,2), -- 0-100 from Risk Engine
  contributing_factors JSONB, -- phishing clicks, training overdue, etc.
  calculated_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_awareness_tenant ON awareness_campaigns(tenant_id);
```

## 5. Service Integrations
- Redis: Cache campaign progress, user risk scores, training content (TTL 1h)
- RabbitMQ: Publish to `awareness-events` queue (campaign.completed, phishing.click, user.high_risk, training.overdue)
- API Gateway: All endpoints routed through `/api/awareness/*`
- Risk Engine: Send user behaviors for risk scoring (HTTP to `risk-engine:8000`)
- IAM Service: Sync users, update user risk profiles, SSO integration
- GRC Service: Map human risks to risk register
- SOAR Service: Trigger playbooks for high-risk users (additional training, manager notification)
- IAM Service: Validate tenant_id from JWT token

## 6. Security Requirements
- All endpoints protected by API Gateway OWASP policies
- Tenant isolation: queries filtered by JWT tenant_id
- Protect phishing simulation data (don't expose clicked links to non-admins)
- Audit logging: all campaign activities logged to `request_logs`
- Encrypt user training data at rest (GDPR compliance)
- mTLS for service-to-service communication
- Role-based access: only security awareness admins can launch simulations

## 7. Deployment
### Dockerfile
```dockerfile
FROM node:18-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production
COPY . .
EXPOSE 3006
HEALTHCHECK --interval=30s --timeout=10s --retries=3 \
  CMD node -e "require('http').get('http://localhost:3006/health', (r) => {process.exit(r.statusCode === 200 ? 0 : 1)})"
CMD ["node", "server.js"]
```
