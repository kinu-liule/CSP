# Business Continuity Platform - Prompt Specification
## Tech Stack Alignment
MUST USE APPROVED STACK:
- Backend: Node.js 18, Express.js, PostgreSQL 16, Redis 7, RabbitMQ 3, JWT, bcryptjs
- Frontend: React 18, React Router 6, Bootstrap 5, Chart.js, React ChartJS 2 (dashboard)
- Infra: Docker (node:18-alpine), Docker Compose, Kubernetes, Nginx Alpine
- Security: OWASP API Top 10, Helmet, Rate Limiting, JWT Auth via API Gateway

## 1. Component Overview
Microservice for managing business continuity planning (BCP), disaster recovery (DR), and operational resilience with automated RTO/RPO tracking, incident response workflows, and compliance reporting across multi-tenant environments.

## 2. Core Requirements
- Business impact analysis (BIA) with critical process identification
- RTO (Recovery Time Objective) and RPO (Recovery Point Objective) definitions per process
- Disaster recovery plan management with versioning
- Incident response workflows integrated with SIEM/SOAR service
- Automated backup verification and compliance checks
- Continuity testing scheduler and results tracking
- Redis caching for frequently accessed plans and metrics
- RabbitMQ event publishing for DR incidents, plan activations, compliance failures

## 3. API Endpoints (routed via API Gateway: /api/bcp/*)
| Method | Endpoint | Description | Auth |
|--------|----------|-------------|------|
| GET | /health | Health check | None |
| GET | /api/bcp/processes | List critical business processes | JWT/API Key |
| POST | /api/bcp/processes | Add new business process | Admin JWT |
| GET | /api/bcp/processes/:id | Get process details with RTO/RPO | JWT/API Key |
| PUT | /api/bcp/processes/:id | Update process RTO/RPO | Admin JWT |
| GET | /api/bcp/plans | List DR plans | JWT/API Key |
| POST | /api/bcp/plans | Create new DR plan | Admin JWT |
| POST | /api/bcp/plans/:id/activate | Activate DR plan | Admin JWT |
| GET | /api/bcp/tests | List continuity tests | JWT/API Key |
| POST | /api/bcp/tests | Schedule new continuity test | Admin JWT |
| GET | /api/bcp/metrics | Get BCP compliance metrics | JWT/API Key |

## 4. Database Schema (PostgreSQL)
```sql
CREATE TABLE bcp_processes (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id UUID REFERENCES tenants(id),
  name VARCHAR(255) NOT NULL,
  description TEXT,
  criticality VARCHAR(20) DEFAULT 'medium', -- low, medium, high, critical
  rto_minutes INT NOT NULL, -- Recovery Time Objective
  rpo_minutes INT NOT NULL, -- Recovery Point Objective
  owner VARCHAR(255),
  dependencies TEXT[] DEFAULT '{}',
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE bcp_plans (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id UUID REFERENCES tenants(id),
  process_id UUID REFERENCES bcp_processes(id),
  name VARCHAR(255) NOT NULL,
  version VARCHAR(20) DEFAULT '1.0',
  content JSONB NOT NULL, -- step-by-step recovery procedures
  status VARCHAR(20) DEFAULT 'draft', -- draft, active, archived
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE bcp_tests (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id UUID REFERENCES tenants(id),
  plan_id UUID REFERENCES bcp_plans(id),
  test_type VARCHAR(50), -- tabletop, functional, full_interruption
  scheduled_date DATE,
  completed_date DATE,
  result VARCHAR(20), -- pass, fail, partial
  findings TEXT,
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE bcp_incidents (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id UUID REFERENCES tenants(id),
  process_id UUID REFERENCES bcp_processes(id),
  incident_name VARCHAR(255),
  severity VARCHAR(20),
  activated_plan_id UUID REFERENCES bcp_plans(id),
  status VARCHAR(20) DEFAULT 'active', -- active, resolved
  created_at TIMESTAMP DEFAULT NOW(),
  resolved_at TIMESTAMP
);

CREATE INDEX idx_bcp_tenant ON bcp_processes(tenant_id);
```

## 5. Service Integrations
- Redis: Cache DR plans, RTO/RPO metrics, test results
- RabbitMQ: Publish to `bcp-events` queue (plan.activated, incident.created, test.completed, compliance.violation)
- API Gateway: All endpoints routed through `/api/bcp/*`
- SIEM/SOAR Service: Send incident alerts, receive security event correlations
- IAM Service: Validate tenant_id from JWT token

## 6. Security Requirements
- All endpoints protected by API Gateway OWASP policies
- Tenant isolation: queries filtered by JWT tenant_id
- Audit logging: plan changes and activations logged to `request_logs`
- Encrypt sensitive DR plan content at rest
- mTLS for service-to-service communication
- Role-based access: only admins can activate DR plans

## 7. Deployment
### Dockerfile
```dockerfile
FROM node:18-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production
COPY . .
EXPOSE 3010
HEALTHCHECK --interval=30s --timeout=10s --retries=3 \
  CMD node -e "require('http').get('http://localhost:3010/health', (r) => {process.exit(r.statusCode === 200 ? 0 : 1)})"
CMD ["node", "server.js"]
```

### Docker Compose Block
```yaml
business-continuity:
  platform: linux/amd64
  build:
    context: ./business-continuity-service
    dockerfile: Dockerfile
  container_name: cybersec-bcp
  ports:
    - "3010:3010"
  environment:
    NODE_ENV: production
    PORT: 3010
    DATABASE_URL: postgresql://cybersec:securepassword@postgres:5432/cybersec_platform
    REDIS_URL: redis://redis:6379
    RABBITMQ_URL: amqp://cybersec:securepassword@rabbitmq:5672
    SIEM_SOAR_SERVICE_URL: http://siem-soar:3003
  depends_on:
    postgres:
      condition: service_healthy
    redis:
      condition: service_healthy
  healthcheck:
    test: ["CMD", "node", "-e", "require('http').get('http://localhost:3010/health', (r) => {process.exit(r.statusCode === 200 ? 0 : 1)})"]
    interval: 30s
    timeout: 10s
    retries: 3
  networks:
    - cybersec-network
```
